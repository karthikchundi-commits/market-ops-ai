# Market Operations Ticket Copilot

AIMLZG 549 *API-driven Cloud Native Solutions*, Assignment II (Group 31).

This is an NLP assistant for the support desk of an electricity market operator (ISO/RTO). Market participants raise tickets about settlements, meter data, offers, invoices, credit, capacity, system access and outages. The copilot handles each ticket in five steps:

| # | Sub-task | Model | Endpoint |
|---|----------|-------|----------|
| 1 | Ticket classification and routing | `distilbert-base-uncased`, **fine-tuned** on our ticket dataset (Part II) | `POST /classify` |
| 2 | Thread summarisation | `sshleifer/distilbart-cnn-12-6` | `POST /summarize` |
| 3 | Entity and market-field extraction | `dslim/bert-base-NER` plus market-specific regex rules | `POST /extract` |
| 4 | RAG chatbot over the PJM manuals (Part III) | `all-MiniLM-L6-v2` embeddings with a FAISS index, then an LLM | `POST /rag/ask` |
| — | **End-to-end triage**, which chains steps 1–4 and drafts a reply | all of the above | `POST /triage` |

All five steps serve one goal: cut the time an analyst spends routing and researching each ticket before they can answer it.

## Architecture

```
Streamlit UI (app/ui.py) ──HTTP──► FastAPI (app/api.py) ──► app/tasks.py
                                                           ├─ fine-tuned DistilBERT  (models/ticket-classifier)
                                                           ├─ DistilBART summariser
                                                           ├─ BERT-NER + regex rules
                                                           └─ FAISS retriever (rag/index) ─► Qwen2.5-1.5B-Instruct on CPU (app/llm.py)
```

## Setup

```bash
python -m venv .venv && .venv/Scripts/activate        # Windows; use .venv/bin/activate on Linux/macOS
pip install -r requirements.txt
python data/generate_tickets.py                       # synthetic dataset -> data/tickets_*.csv
python training/finetune_classifier.py --epochs 3     # Part II -> models/ticket-classifier, reports/
python rag/build_index.py                             # Part III -> downloads PJM manuals, builds rag/index
```

## Run

```bash
uvicorn app.api:app --port 8000          # API; interactive docs at http://localhost:8000/docs
streamlit run app/ui.py                  # UI at http://localhost:8501
python scripts/evaluate.py               # Part IV evaluation -> reports/evaluation.json
```

To use a different local model, set `LOCAL_LLM=<hf model id>` (e.g. `Qwen/Qwen2.5-0.5B-Instruct` on machines with less than 14 GB RAM).

## Data

* **Tickets:** synthetic and anonymised, generated by `data/generate_tickets.py` (8 categories, 64 templates). Two templates per category never appear in training and are used only for the test split, so the test score measures how well the model handles new phrasings.
* **RAG corpus:** public PJM manuals: M11 (Energy & Ancillary Services Market Operations), M18 (Capacity Market), M28 (Operating Agreement Accounting) and M29 (Billing).
